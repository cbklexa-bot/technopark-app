# Коптильня — быстрый запуск владельца

## Где находится рабочая ветка

Исходный проект: `cbklexa-bot/technopark-app`.
Рабочая ветка: `koptilnya-production`.

Не переносить этот код в `main` до проверки входа в общей Auth-системе, облачного сохранения после перезапуска и импорта Excel.

## Почему тестовый APK и готовый рабочий APK — не одно и то же

Рабочая ветка: `koptilnya-production` в репозитории `cbklexa-bot/technopark-app`.

Для Коптильни используется существующий Supabase-проект ТехноПарка `cbklexa-bot's Project` (`ereiiidezagburttpxtn`, регион `eu-central-1`). Все новые таблицы, индексы, представления и RPC-функции Коптильни имеют префикс `kp_`; таблицы `tp_*` ТехноПарка не изменяются. Не подключать `max-song-app`.

Для Android-сборки в `smokehouse-android/www/cloud-config.js` используются только URL проекта и публичный publishable key. Service-role/secret keys в приложение или публичный GitHub помещать нельзя. Перед стартом проверь регистрацию, подтверждение email при включённой проверке, вход, создание рабочей области, сохранение/повторное чтение данных и экспорт резервной копии.

Перед фактическим запуском проверь:
1. Email/password sign-up, email/password sign-in и восстановление пароля.
2. Создание первой организации и чтение/сохранение `kp_organization_data`.
3. Успешный save с инкрементом revision после изменения карточки или документа.
4. Отказ при конфликте старой revision и отказ в чтении/записи чужой организации.
5. Повторный вход и перезапуск Android с восстановлением облачных данных.
6. Экспорт ZIP до замещения данных импортом.

Настройка подтверждения почты в hosted Supabase должна соответствовать выбранному способу получения писем. Если email confirmation включён, пользователь должен подтвердить почту до первого входа; стандартный тестовый SMTP Supabase не является надёжным производственным почтовым сервером.

## Импорт рабочей книги Excel

Импорт запускается кнопкой «Импорт Excel» после входа в аккаунт. Файл разбирается на устройстве. Перед заменой состояния приложения формируется ZIP-резервная копия; при ошибке сервера импорт не должен подтверждаться.

Распознаются листы:
- Продукция / Товары.
- Остатки / Остатки продукции.
- Клиенты / Контрагенты.
- Документы / Накладные.
- Позиции / Позиции накладных.
- Затраты / Расходы.
- Оплаты / Платежи.
- Партии / Производство / Выпуск.
- Контрольные суммы и расхождения.

Листы «Сводка», «Продажи», «Услуги» и «По месяцам» служат для сравнения и не импортируются как дополнительные операции. Они не должны повторно увеличивать выручку.

Активный справочник содержит ровно шесть названий:
`Тортика`, `Деревенька`, `Пекарня`, `Кочевник`, `Наш`, `Клиенты цеха`.
Другие имена остаются только в исторических реквизитах документов и не появляются в активном справочнике.

Импорт блокируется, если нет листа исходных документов, невозможно сопоставить позиции, имеются опасные повторы ключей или неоднозначно распределены платежи по повторяющимся номерам документов. Прежде чем разблокировать такой импорт, нужно сопоставить строки с оригиналом и не менять финансовые значения для прохождения тестов.

Годовые итоги 2025 и 2026 считаются из исходных документов; оплаченные суммы не прибавляются к выручке второй раз. Производственные партии, закупка сырья, выпуск продукции, расход запасов, продажи, себестоимость и дополнительные затраты считаются раздельно.
