# Технопарк PRO — админка

## Что уже сделано

- Supabase Auth вместо пароля, зашитого в JavaScript.
- RLS для `tp_stock`, `tp_sessions`, `tp_sales`, `tp_expenses`.
- Админские policies используют `raw_app_meta_data.role = admin`.
- В арендах появился отдельный `service_code`; старые записи были автоматически нормализованы.
- У завершённых аренд есть `finished_at`.
- У расходов есть отдельные `expense_date` и `category`.
- Финансовая аналитика работает по дню, текущему/историческому месяцу и показывает экономику день-за-днём.
- История выбора периода доступна за последние 36 месяцев.
- Попкорн добавлен в склад как товар с ценой 150 ₽.
- Добавлены проверки БД: количество, цены, себестоимость и суммы не могут становиться отрицательными.

## Первый вход администратора

В Supabase откройте **Authentication → Users → Add user** и создайте отдельную email/password учётку администратора.

После создания выдать ей роль:

```sql
UPDATE auth.users
SET raw_app_meta_data =
      COALESCE(raw_app_meta_data, '{}'::jsonb)
      || jsonb_build_object('role', 'admin'),
    updated_at = now()
WHERE email = 'EMAIL_АДМИНИСТРАТОРА';
```

После изменения роли выйдите из приложения и войдите заново, чтобы JWT получил свежий `app_metadata`.

## Расходы за прошлые месяцы

Раздел **Админ → Расходы** позволяет указать отдельную дату расхода. Поэтому расход можно внести задним числом, например:

- 15.09.2026 — аренда;
- 28.09.2026 — зарплата;
- 30.09.2026 — электричество.

Отчёт сентября будет учитывать такие расходы по `expense_date`, а не по дате, когда запись была внесена в систему.

## Важный принцип безопасности

Не помещайте `service_role`/secret key в браузер. В клиенте используется только publishable key. Supabase рекомендует совмещать grants и RLS, а авторизационные данные держать в `raw_app_meta_data`, а не в пользовательских metadata.
